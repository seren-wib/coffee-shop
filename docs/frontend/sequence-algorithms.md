# 프론트엔드 시퀀스 알고리즘 설계

## 1. 공통 처리 알고리즘

1. 사용자 입력값(필수 항목, 형식, 수량 등)을 검증하고, 유효하지 않으면 오류 메시지를 표시한다.
2. 검증을 통과하면 React UI에서 Django API로 요청을 전송한다.
3. 인증이 필요한 요청에서 HTTP 401 발생 시 토큰 재발급을 시도하고, 성공하면 원래 요청을 한 번 재시도한다. 실패하면 로그인 화면으로 이동한다.
4. 정상 응답 시 결과에 따라 목록·상세 정보·주문 상태 등 화면 데이터를 갱신한다.
5. 요청 실패 시 오류 사유를 안내하고, 필요한 경우 재입력 또는 재시도를 제공한다. 백엔드 내부 처리는 메소드 알고리즘 설계를 참조한다.

## 2. 시나리오별 처리 차이

| 구분 | 프론트엔드 처리 |
|---|---|
| SEQ-01 | 로그인·회원가입 결과에 따라 인증 상태 또는 입력 오류 표시 |
| SEQ-02 | 검색·필터 결과를 20개 단위로 표시하고 상품 상세·재고 갱신 |
| SEQ-03 | 옵션·수량 선택 후 장바구니 갱신, 품절·재고 부족 안내 |
| SEQ-04 | 주문·결제 결과에 따라 완료·환불·실패 및 재시도 화면 표시 |
| SEQ-05 | 주문 목록·배송 정보 표시, 주문 상태별 취소 결과 반영 |
| SEQ-06 | 회원정보·비밀번호 변경 결과 및 배송지 목록 갱신 |
| SEQ-07 | 관리자 상품·옵션 등록 및 수정 결과 표시 |
| SEQ-08 | 재고 변경과 판매·품절 상태를 화면에 반영 |
| SEQ-09 | 배송 처리·완료 및 취소 승인·반려 결과를 주문 목록에 반영 |
