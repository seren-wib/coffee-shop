## 11. 설계 근거

기술 결정이다. 바뀌면 옛 항목은 두고 새 항목을 단다. 요구사항 수준 정책은 SRS 7절에 있다.

### 11.1 확정

- 2026-11-17: Cloudflare 프록시를 켜고 SSL/TLS 모드는 Full (strict)로 한다. 원 서버(EC2)에는 Cloudflare Origin CA 인증서를 둔다. HTTP → HTTPS 전환은 Cloudflare의 Always Use HTTPS로 한다(NFR-4, NFR-5). 버린 것: DNS only + 서버에서 Let's Encrypt(인증서 갱신 작업이 생기고 EC2 주소가 DNS로 그대로 드러남), Flexible 모드(Cloudflare와 EC2 사이가 평문). 이유: 유지보수성(인증서 갱신 없음), 보안(공개 레포라 원 서버 주소를 숨기는 편이 낫다). (커피샵 Lead 결정, 팀장 위임)
- 2026-11-17: 운영 환경은 서울 리전(ap-northeast-2)의 EC2 t3.micro 한 대, Ubuntu 24.04 LTS, Elastic IP 하나다. 인스턴스 안에서 nginx가 프론트엔드 빌드 결과(정적 파일)를 `/`로, `/api/`는 gunicorn(Django)으로 넘긴다. 버린 것: 프론트엔드를 S3·CloudFront로 따로 배포(서비스가 둘로 늘고 도메인 라우팅이 복잡해짐), Vite 개발 서버 그대로 운영(개발용이라 운영에 맞지 않음), Elastic IP 없이 자동 공인 IP(인스턴스를 멈췄다 켜면 주소가 바뀌어 DNS를 다시 고쳐야 함). 이유: 종속성(서비스 하나), 유지보수성(SIP 절차가 짧음). 비용은 SPMP 4절. (커피샵 Lead 결정, 팀장 위임)
- 2026-11-17: 운영 DB는 SQLite를 그대로 쓴다. WAL 모드를 켜고, 하루 한 번 `sqlite3 .backup`으로 백업 파일을 만들어 7개를 남긴다(NFR-25). 버린 것: RDS(비용과 설정이 늘고, 시연 규모에선 동시 쓰기 부하가 작음). 이유: 비용, 종속성. NFR-15 동시 주문 테스트에서 잠금 오류가 나면 다시 정한다. (커피샵 Lead 결정, 팀장 위임)
- 2026-11-17: `users.User`를 Django 커스텀 사용자 모델(`AbstractBaseUser` + `PermissionsMixin`, `AUTH_USER_MODEL = "users.User"`)로 바꾸고 이메일을 로그인 ID로 쓴다. 비밀번호 열은 Django 규칙대로 `password`가 된다(SRS NFR-6 측정 열 이름도 같이 고친다). 버린 것: 지금 모델을 두고 로그인 처리를 직접 작성(토큰 발급, 해시 확인, 권한 확인을 따로 만들어야 하고 simplejwt와 어긋남). 이유: 유지보수성, 테스트 용이성. 아직 마이그레이션이 없어서 지금 바꾸는 비용이 가장 작다. (커피샵 Lead 결정, 팀장 위임)
- 2026-11-17: 운영 환경에서는 Django 관리 사이트(`/admin/`)를 URL에서 빼고, 개발 환경에서만 연다. 관리자 업무는 FR-36 ~ FR-51, FR-56, FR-57 화면으로, 관리자 계정은 관리 명령(FR-53)으로 만든다. 버린 것: 운영에서도 `/admin/` 공개(공격 대상 경로가 하나 늘고, 화면과 별도로 권한을 두 번 관리해야 함). 이유: 보안, 테스트 용이성. (커피샵 Lead 결정, 팀장 위임)
- 2026-11-17: 테이블 정의의 원본은 `backend/*/models.py`와 Django 마이그레이션이다. `backend/schema.sql`은 지우고, 필요하면 `sqlmigrate`로 뽑아 본다. 부분 유니크 인덱스(기본 배송지 하나, 성공 결제 하나)와 CHECK 제약은 모델 `Meta.constraints`로 둔다. 버린 것: `schema.sql`을 원본으로 두기(ORM과 이중 관리, 이미 두 곳이 서로 다름). 이유: 유지보수성, 배포 때 `migrate` 한 번으로 끝남. (커피샵 Lead 결정, 팀장 위임)
- 2026-11-17: `TIME_ZONE = "Asia/Seoul"`, `USE_TZ = True`로 하고, 주문번호 날짜(DR-11)는 `timezone.localdate()`로 정한다. 버린 것: UTC 유지(자정 전후 주문의 날짜가 한국 날짜와 하루 어긋남). 이유: DR-11. (커피샵 Lead 결정, 팀장 위임)
- 2026-11-17: 옵션 용량 저장값을 `200G`, `500G`, `1KG` 코드로 한다(5.0.2절). 버린 것: `'200g'` 문자열(다른 열거형과 규칙이 다르고, CHECK 값과 표시 문자열이 섞임). 이유: 유지보수성. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 주문 시각 열 이름을 `ordered_at`에서 `created_at`으로 바꾼다(5.6절). 버린 것: 모델은 `ordered_at`, API만 `created_at`(모델과 API 이름이 갈라짐). 이유: SRS FR-30, FR-44 검증 열과 다른 테이블 이름에 맞춤. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 택배사는 코드 `courier_code`(5개)로 저장하고, API는 한국어 이름 `courier_name`과 서버가 만든 `tracking_url`을 내보낸다(5.6절, 5.10절). 버린 것: 자유 문자열(조회 링크를 만들 수 없음, SRS 7.1 고정 목록과 어긋남). 이유: 테스트 용이성. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 결제 시도마다 PG 주문 번호 `pg_order_id = <주문번호>-P<n>`을 두고, `payment_method`는 NULL 허용, `payments.order_id`는 PROTECT로 한다(4.6.1절, 5.8절). 버린 것: 주문번호를 그대로 토스 `orderId`로 쓰기(토스 오류 코드 `DUPLICATED_ORDER_ID` 때문에 재결제가 막힘), CASCADE(환불 근거인 결제 기록이 주문과 함께 지워짐). 이유: DR-24 재결제, NFR-17과 같은 보존 원칙. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 관리자 취소 승인은 PG 취소를 먼저 하고 DB를 나중에 바꾼다. PG 취소에는 `Idempotency-Key`를 붙인다(4.8.7절, 4.6.6절). 버린 것: DB 먼저(PG 오류 때 "주문 취소, 결제 성공"이 남고 다시 시도할 경로가 없음). 받아들인 한계: 관리자 둘이 동시에 승인·반려하면 어긋날 수 있음(관리자 계정은 하나). 다시 정하는 신호: 3.2절 스파이크 3·7단계에서 두 번째 취소가 성공으로 오지 않을 때, 관리자 계정이 둘 이상이 될 때. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 토큰은 `localStorage`에 두고, 리프레시 토큰 돌려쓰기·폐기 목록은 쓰지 않는다(4.1.3절, 4.1.5절). XSS는 CSP로 막는다(8.6절). 버린 것: httpOnly 쿠키(CSRF 대책과 쿠키 설정이 새로 필요하고, SRS FR-54가 브라우저 저장소의 토큰 삭제를 검증함), simplejwt blacklist(로그아웃마다 DB 쓰기, 테이블 둘 추가). 이유: 종속성, 테스트 용이성. 다시 정하는 신호: 실제 사용자 운영으로 넘어갈 때. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 관리자 재고 조정은 새 재고 수량을 보낸다. 옵션 추가도 `set_stock`을 거친다(4.7.4절, 4.7.8절). 버린 것: 증감량 전송(화면이 "+10" 입력을 따로 받아야 함). 받아들인 한계: 관리자가 화면을 보는 사이 주문으로 줄어든 재고를 덮어쓸 수 있음(시연 규모). (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 원산지 선택지는 프론트엔드 고정 목록이다(4.3.7절). 버린 것: 원산지 목록 API(경로 하나 추가, SRS 6.2에 없음). 받아들인 한계: 목록 밖 원산지로 등록한 원두는 원산지 필터로 찾을 수 없음. 시드 데이터와 관리자 화면의 원산지 입력도 같은 목록에서 고르게 한다. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: EC2 보안 그룹은 443을 Cloudflare 주소 대역에만, 22를 운영자 주소에만 연다. Cloudflare 대역이 바뀌면 보안 그룹과 nginx `cloudflare-real-ip.conf`를 함께 바꾼다(8.3절, SMP 1절). 버린 것: 443 전체 공개(Full strict여도 원 서버로 바로 오는 요청을 받음). 이유: 보안. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 주문 생성은 장바구니 전체를 대상으로 하고, 판매 중지·품절·재고 초과 항목이 하나라도 있으면 409로 거절한다. 장바구니 상품 금액은 모든 항목의 합이다(4.5.3절, 4.4.2절). 버린 것: 주문 가능한 항목만 골라 주문(SRS FR-23 검증 "한 항목이라도 재고 부족이면 409", NFR-14, NFR-16 검증과 어긋남). 남은 일: SRS FR-23 본문 "주문 가능한 모든 항목"을 "장바구니의 모든 항목"으로 고치는 SRS PR(2026-11-19 반영). (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 로그인은 IP당 분당 10회, 가입은 IP당 시간당 20회로 제한하고 넘으면 429다(8.3절). 테스트 설정은 한도를 크게 잡는다. 버린 것: 제한 없음(비밀번호 대입 공격에 그대로 열림), 계정별 잠금(공격자가 남의 계정을 잠글 수 있음). 이유: NFR-7 보강. 받아들인 한계: 로컬 메모리 캐시라 gunicorn 워커마다 따로 셈. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 결제 금액이 다르면 SRS FR-27 검증대로 승인한 뒤 PG에 취소를 요청한다(4.6.3절). 버린 것: 승인 전에 서버 저장 금액과 비교해 막기(토스 가이드가 권하지만 SRS FR-27 검증 "금액이 다른 확인 요청 후 결제 `CANCELLED`"와 결과 상태가 다름). 다시 정하는 신호: 3.2절 스파이크 4단계에서 토스가 다른 금액의 승인을 거절하면, 승인 전 비교로 바꾸고 SRS FR-27 검증을 고친다. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 운영 수치를 gunicorn sync 워커 3개, 요청 시간 제한 30초, 스왑 1GiB로 하고, `last_login`은 갱신하지 않는다(10.2절, 4.1.2절). 워커 메모리는 하나에 60 ~ 80MB로 추정했고 안 쟀다. 이유: t3.micro 메모리 1GiB, 로그인마다 쓰기 잠금을 잡지 않음. 다시 정하는 신호: NFR-1 측정 때 메모리·응답 시간. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: SRS에 없는 보조 동작 셋을 둔다. 관리자 원두 목록의 `sales_status` 필터(4.7.1절), 취소 요청 탭 건수 배지(4.8.2절), 하루 999건 초과 시 503 `ORDER_LIMIT`(4.5.2절). SRS 요구를 어기지 않고 화면 와이어프레임(SCR-11 상태 필터)과 DR-11 세 자리 규칙에서 나온다. (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 설계에 필요한 경로 두 개 `POST /api/payments/fail/`(4.6.4절), `GET /api/admin/products/{id}/`(4.7.12절)를 둔다(7.7절). 버린 것: 결제창 실패를 기록하지 않음(FR-28 검증을 결제창 실패에서 만족 못 함), 관리자 수정 화면을 목록 응답으로 채우기(목록 형식이 커짐). 남은 일: SRS 6.2에 두 경로를 더하는 SRS PR(FR-23 본문 수정과 함께, 2026-11-19 반영). (SDD 세션 결정, 팀장 위임 2026-11-17)
- 2026-11-17: 이번 학기 배포는 운영자가 서버에서 `deploy/deploy.sh <태그>`를 실행하는 수동 배포다(10.4절). 버린 것: GitHub Actions에서 빌드 후 SSH로 올리기(Actions 시크릿에 SSH 키를 두고 22번을 GitHub 주소 대역에 열어야 함, CI가 아직 없음). 이유: 보안, 종속성. 다시 정하는 신호: STP 7절 CI가 들어올 때. (SDD 세션 결정, 팀장 위임 2026-11-17)
