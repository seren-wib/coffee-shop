## 12. 클래스·모듈 명세

백엔드(`backend/`)의 클래스와 모듈을 코드 구조대로 적는다. 4절이 "요청이 오면 무슨 일이 일어나는가"를 기능 단위로 적은 것이라면, 이 절은 "어느 클래스와 함수가 그 일을 맡는가"를 코드 단위로 적는다. 처리 순서와 규칙은 4절이 원본이고 여기서 다시 적지 않는다. 두 절은 요구사항 ID(FR, DR, NFR)로 잇는다. 같은 ID가 달린 4절 소절이 그 함수의 처리 설명이다.

### 12.0 표기 규칙

- 단위: 업무 규칙은 클래스 메서드가 아니라 모듈 함수(`services.py`, `payments.py`, `queries.py`)에 있다(디렉터리 규칙). 그래서 서비스는 모듈을 단위로 삼아 함수를 적고, 모델·뷰·시리얼라이저는 클래스를 단위로 적는다.
- 공개 함수: 소제목 아래 세 줄을 적는다. 시그니처, 반환과 예외, 요구사항 ID. 매개변수는 이름만으로 뜻이 드러나지 않을 때만 풀어 적는다.
- 내부 함수: 이름이 밑줄로 시작하고 같은 모듈 안에서만 부른다. 이름과 하는 일을 한 줄로 적는다.
- 예외: 업무 규칙 위반은 `DomainError(code, message, status)`로 던진다(12.4.1). "409 `OUT_OF_STOCK`"처럼 상태 코드와 오류 코드로 적는다. 입력 형식 오류는 시리얼라이저가 400 `VALIDATION_ERROR`로 먼저 막으므로 서비스 함수에는 적지 않는다.
- 트랜잭션: 따로 적지 않으면 함수 전체가 `transaction.atomic()` 한 번이다. 아닌 함수만 "트랜잭션 밖"이라고 적는다.
- 모델: 열과 제약은 데이터 모델 절이 원본이다. 여기에는 클래스 이름, 맡는 일, 테이블, 직접 정의한 메서드만 적는다.
- 뷰: 클래스 하나가 경로 하나다. HTTP 메서드, 부르는 서비스 함수, 요구사항 ID를 표 한 줄로 적는다. 권한은 따로 적지 않으면 로그인한 회원(`IsAuthenticated`)이다.
- 시리얼라이저: 클래스 이름과 맡는 일을 표 한 줄로 적는다.
- 이 절의 이름과 시그니처는 코드와 글자까지 같아야 한다. 코드가 바뀌면 같은 PR에서 이 절을 고친다.
