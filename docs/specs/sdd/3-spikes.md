## 3. 스파이크

SPMP 5절(위험 관리)은 아직 비어 있어서 SPMP가 정한 핵심 불확실성은 없다. 이 설계에서 구현 전에 확인해야 하는 기술 질문은 아래 두 가지다. 2026-11-17 현재 둘 다 **아직 돌리지 않았고**, 결과 칸은 비워 둔다. 코드는 `spikes/<이름>/`에 커밋하고, README 첫 줄에 질문과 답을 적는다. 결과가 나오면 이 절과 11절을 같은 PR에서 고친다.

### 3.1 sqlite-concurrent-order

- 질문: SQLite(WAL)와 gunicorn 워커 3개에서, 재고 1개 옵션에 동시 주문 10건이 들어오면 성공 1건, 재고 0, 나머지는 잠금 오류 없이 409로 끝나는가(NFR-15)?
- 결론: **아직 돌리지 않았다.**
- 방법(계획): Django 6.1, Python 3.12, `DATABASES["default"]["OPTIONS"]`에 `transaction_mode="IMMEDIATE"`, `timeout=20`, `init_command`로 WAL 설정. 4.5.3절의 `create_order`를 그대로 쓰고, gunicorn 워커 3개 앞에서 스레드 10개가 동시에 `POST /api/orders/`를 보낸다. 같은 실험을 `transaction_mode` 기본값(DEFERRED)으로도 한 번 돌려 비교한다.
- 결과:

| 단계 | 확인 | 결과 |
| --- | --- | --- |
| 1 | IMMEDIATE, 동시 10건: 201 개수, 409 개수, 500 개수 | 안 잼 |
| 2 | 1 뒤 옵션 재고, 주문 행 수 | 안 잼 |
| 3 | DEFERRED, 동시 10건: `database is locked` 발생 횟수 | 안 잼 |
| 4 | IMMEDIATE, 동시 10건 응답 시간 p95 | 안 잼 |

- 설계에 반영한 사실: 아직 없음. 지금 설계는 SQLite가 쓰기 트랜잭션을 하나씩만 허용한다는 문서상 성질과, 조건부 UPDATE(`WHERE stock_quantity >= n`)로 비교와 차감을 한 문장에서 끝낸다는 두 겹 방어에 기댄다(4.7.6절).
- 남은 선택: 1단계에서 500(잠금 오류)이 나오면 `timeout`을 늘리거나 워커 수를 줄인다. 그래도 나면 11.1절 SQLite 결정의 재검토 신호다.

### 3.2 toss-confirm-cancel

- 질문: 토스페이먼츠 테스트 키로 (1) 결제창 → `successUrl` 복귀 → 서버 승인, (2) 승인 뒤 전액 취소, (3) 같은 결제를 두 번 취소했을 때의 오류 코드, (4) 결제창에서 연 금액과 다른 금액으로 승인 요청했을 때의 응답이 4.6절 설계대로 오는가?
- 결론: **아직 돌리지 않았다.**
- 방법(계획): 토스페이먼츠 결제창 SDK(본문 4.6.2와 같은 결제창 방식)와 테스트 키(개발자 센터에서 발급, 값은 레포 밖). 로컬 Vite 개발 서버에서 결제창을 열고, 백엔드의 `TossPaymentsClient`로 승인·취소를 부른다.
- 결과:

| 단계 | 확인 | 결과 |
| --- | --- | --- |
| 1 | 테스트 카드 결제 후 `successUrl`에 `paymentKey`, `orderId`, `amount`가 붙어 오는가 | 안 잼 |
| 2 | 승인 응답의 `totalAmount`, `method`, `approvedAt` 값과 형식 | 안 잼 |
| 3 | 전액 취소 응답, 같은 결제 두 번째 취소의 오류 코드 | 안 잼 |
| 4 | 결제창 금액과 다른 `amount`로 승인 요청한 응답 | 안 잼 |
| 5 | 실패·이탈 시 `failUrl`에 붙는 값(창 닫기에 `orderId`가 없는지) | 안 잼 |
| 6 | 결제 요청 뒤 10분이 지난 `paymentKey`로 승인한 응답 | 안 잼 |
| 7 | 같은 `Idempotency-Key`로 취소를 두 번 보낸 응답 | 안 잼 |

- 설계에 반영한 사실: 스파이크는 아직 없음. 4.6절의 필드 이름, 오류 코드(`ALREADY_PROCESSED_PAYMENT`, `ALREADY_CANCELED_PAYMENT`, `DUPLICATED_ORDER_ID`), 10분 승인 제한, `Idempotency-Key`는 토스페이먼츠 공개 문서(API 레퍼런스, 오류 코드 표, 결제위젯 연동 가이드)를 기준으로 썼다. 응답이 다르면 4.6절과 `orders/pg.py`를 같은 PR에서 고친다.
- 남은 선택: 3·7단계에서 두 번째 취소가 성공으로 돌아오지 않으면 4.8.7절의 취소 승인 순서(PG 취소 먼저)를 다시 본다. 4단계에서 토스가 다른 금액의 승인을 거절하면 FR-27 검증을 어떻게 만족할지 11.1절대로 다시 정한다.
