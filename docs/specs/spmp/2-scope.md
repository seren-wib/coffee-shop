## 2. 목표와 범위

텀프로젝트 마감(2026-11-30 23:50)까지 SRS의 기능·비기능 요구사항을 모두 구현하고, 운영 환경(EC2)에 배포해 평가자가 인터넷에서 직접 써볼 수 있게 한다. 요구사항 ID를 설계(SDD), 테스트(STP), PR까지 추적해 무엇이 어디서 확인됐는지 남긴다. 결제는 실제 돈이 오가지 않는 테스트 모드로 하고, 화면 맨 위에 데모라는 사실을 알린다(NFR-36).

### 2.1 범위 안

이번 학기 범위를 모두 1차로 두고 차수는 나누지 않는다(SRS 7.1절). 2차, 3차는 없다.

| 영역 | 요구사항 |
| --- | --- |
| 원두 조회(비회원 포함) | FR-1 ~ FR-6 |
| 회원과 배송지, 개인정보 동의 | FR-7 ~ FR-18, FR-54, FR-58 |
| 장바구니 | FR-19 ~ FR-22 |
| 주문과 결제(토스페이먼츠 테스트 모드, 키 없으면 결제 끔) | FR-23 ~ FR-33, FR-55, FR-60 |
| 배송 조회(택배사 조회 페이지 링크) | FR-34, FR-35 |
| 관리자 원두·옵션·재고 관리 | FR-36 ~ FR-43, FR-56 |
| 관리자 주문·배송·취소 처리 | FR-44 ~ FR-51, FR-57 |
| 운영(상태 확인, 관리자 생성, 개인정보 처리방침, 배포·롤백·복원) | FR-52, FR-53, FR-59, FR-61 ~ FR-63 |
| 비기능: 성능, 보안, 신뢰성, 개인정보, 호환, 운영, 가용성, 유지보수(CI 포함), 품질 | NFR-1 ~ NFR-43 |
| 데이터 규칙과 사용 사례 | DR-1 ~ DR-24, UC-1 ~ UC-15 |

### 2.2 범위 밖

이번 학기에는 아무도 맡지 않는다. 다음 학기나 실제 운영으로 넘어갈 때 다시 본다.

- 실제 결제: 사업자 등록과 PG 계약이 필요하다. 테스트 키로만 결제한다(SRS 7.1절).
- 택배사 API 연동: API 키 발급과 택배사별 형식 차이. 조회 페이지 링크로 대신한다(SRS 7.1절).
- 결제 대기 주문의 시간 경과 자동 취소: 재고는 회원이 취소할 때 되돌린다(SRS 7.1절).
- 장바구니 항목 골라 주문: 장바구니 전체로만 주문한다(SRS 7.1절, HW1 와이어프레임).
- PG 웹훅 수신: 결제창 복귀 뒤 서버 승인으로 대신한다(SRS 7.1절).
- 이용약관: 실제 거래 조건이 없어 두지 않는다. 개인정보 동의와 처리방침만 둔다(SRS 7.1절).
- 상품 이미지 파일 업로드: 이미지 URL 한 칸으로 대신한다(SRS 7.1절).
- 최신 Chrome(데스크톱) 밖 브라우저와 모바일 화면 보장(NFR-26).
- (2026-11-27 범위 안으로 옮김, FR-61. 이전에는 "GitHub Actions 자동 배포: 운영자가 서버에서 배포 스크립트를 실행한다(SDD 12.1절)")
