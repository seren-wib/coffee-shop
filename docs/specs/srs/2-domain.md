## 2. 도메인 요구사항

커피 원두 판매 업무에서 어디서나 지키는 규칙이다. 상태 값의 영어 이름은 SDD 데이터 모델을 따른다.

### 2.1 원두와 옵션

| ID | 요구사항 |
| --- | --- |
| DR-1 | 로스팅 정도는 라이트(`LIGHT`), 미디엄(`MEDIUM`), 다크(`DARK`) 중 하나다. |
| DR-2 | 원두는 용량과 분쇄도를 조합한 옵션 단위로 판매한다. 용량은 200g, 500g, 1kg, 분쇄도는 홀빈(`WHOLE_BEAN`), 핸드드립용(`HAND_DRIP`), 에스프레소용(`ESPRESSO`)이다. |
| DR-3 | 한 원두 안에서 같은 용량과 분쇄도 조합의 옵션은 하나만 둔다. |
| DR-4 | 옵션 가격은 원두 기본 가격에 옵션 추가 금액을 더한 값이다. 추가 금액은 0원 이상이다. |
| DR-5 | 재고는 옵션별로 관리하며 0개 밑으로 내려가지 않는다. |

### 2.2 판매 상태

| 상태 | 의미 | 바뀌는 조건 |
| --- | --- | --- |
| 판매 중 (`ON_SALE`) | 주문할 수 있음 | 기본값. 품절 상태에서 재고가 다시 생기면 자동으로 돌아온다 |
| 품절 (`SOLD_OUT`) | 모든 옵션의 재고가 0개 | 판매 중인 원두의 마지막 재고가 팔리면 자동으로 바뀐다 |
| 판매 중지 (`STOPPED`) | 관리자가 판매를 멈춤 | 관리자만 바꾸고 해제한다. 해제할 때 모든 옵션 재고가 0개면 품절로 바뀐다 |

| ID | 요구사항 |
| --- | --- |
| DR-6 | 판매 상태는 위 표의 조건으로만 바뀐다. 품절은 관리자가 직접 바꾸지 않는다. |
| DR-7 | 판매 중지는 재고 변화로 자동 해제되지 않는다. |
| DR-8 | 판매 중지되거나 품절된 원두, 재고가 0개인 옵션은 장바구니에 담거나 주문할 수 없다. |

### 2.3 장바구니와 주문

| ID | 요구사항 |
| --- | --- |
| DR-9 | 장바구니에 이미 있는 옵션을 다시 담으면 새 항목을 만들지 않고 수량을 더한다. |
| DR-10 | 주문 수량은 옵션마다 1개 이상이며, 그 옵션의 남은 재고를 넘을 수 없다. |
| DR-11 | 주문번호는 `ORD-주문일(YYYYMMDD)-일련번호` 형식이다. 일련번호는 세 자리이며 날마다 001부터 다시 매긴다(예: `ORD-20261011-001`). 주문일은 한국 표준시(KST) 기준이다. |
| DR-12 | 주문 항목에는 주문 당시 원두 이름, 옵션, 단가를 복사해 저장한다. 원두 정보나 가격이 바뀌어도 만들어진 주문은 바뀌지 않는다. |

### 2.4 금액과 배송비

| ID | 요구사항 |
| --- | --- |
| DR-13 | 모든 금액은 원 단위 정수로 계산한다. |
| DR-14 | 배송비는 주문 한 건당 3,000원이며, 상품 금액이 30,000원 이상이면 0원이다. |
| DR-15 | 최종 결제 금액은 상품 금액에 배송비를 더한 값이다. |

### 2.5 배송지

| ID | 요구사항 |
| --- | --- |
| DR-16 | 배송지가 있는 회원의 기본 배송지는 항상 하나다. 처음 등록한 배송지는 자동으로 기본 배송지가 되고, 새 배송지를 기본으로 정하면 기존 기본 배송지는 해제된다. |
| DR-17 | 배송지가 둘 이상이면 기본 배송지는 다른 배송지를 기본으로 정한 뒤에만 삭제할 수 있다. 배송지가 하나뿐이면 바로 삭제할 수 있다. |
| DR-18 | 주문에는 주문 당시 받는 사람, 연락처, 주소를 복사해 저장한다. 회원이 나중에 배송지를 고치거나 지워도 주문의 배송지는 바뀌지 않는다. |

### 2.6 주문 상태 전환

| 현재 상태 | 다음 상태 | 하는 사람 | 조건과 처리 |
| --- | --- | --- | --- |
| (없음) | 결제 대기 (`PENDING`) | 회원 | 주문을 만들 때 옵션 재고를 차감한다 |
| 결제 대기 | 결제 완료 (`PAID`) | 시스템 | 결제가 성공하고, 결제된 금액이 최종 결제 금액과 같아야 한다 |
| 결제 대기 | 취소 (`CANCELLED`) | 회원 | 관리자 승인 없이 바로 취소하고 재고를 되돌린다 |
| 결제 완료 | 배송 준비 (`PREPARING`) | 관리자 | 상품 포장을 시작한다 |
| 결제 완료, 배송 준비 | 취소 요청 (`CANCEL_REQUESTED`) | 회원 | 요청 전 상태와 취소 사유를 함께 저장한다 |
| 취소 요청 | 취소 | 관리자 | 승인. 재고를 되돌리고 성공한 결제를 취소한다 |
| 취소 요청 | 요청 전 상태 | 관리자 | 반려. 결제 완료나 배송 준비 중 요청했던 상태로 돌아간다 |
| 배송 준비 | 배송 중 (`SHIPPED`) | 관리자 | 택배사와 송장번호를 등록해야 한다. 출고 시각을 기록한다 |
| 배송 중 | 배송 완료 (`DELIVERED`) | 관리자 | 배송 완료 시각을 기록한다 |

| ID | 요구사항 |
| --- | --- |
| DR-19 | 주문 상태는 위 표에 있는 전환만 허용하고, 나머지 전환은 거부한다. |
| DR-20 | 배송 중부터는 취소를 요청할 수 없다. 취소와 배송 완료는 마지막 상태다. |
| DR-21 | 같은 취소 요청이나 승인이 두 번 들어와도 재고는 한 번만 되돌린다. |

### 2.7 결제

| ID | 요구사항 |
| --- | --- |
| DR-22 | 결제는 결제 대기 상태의 주문에만 할 수 있다. 이미 취소된 주문에 결제 성공 응답이 와도 주문 상태를 바꾸지 않는다. |
| DR-23 | 결제는 성공했지만 주문이 이미 취소되었거나 결제된 금액이 최종 결제 금액과 다르면, 그 결제를 취소하고 환불한다. |
| DR-24 | 결제가 실패하면 주문은 결제 대기로 남고 회원은 다시 결제할 수 있다. 시도마다 결제 기록이 한 건씩 남고, 한 주문에서 성공한 결제는 한 건뿐이다. |
