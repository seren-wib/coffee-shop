### 3.4 주문과 결제 (1차)

| ID | 요구사항 | 검증 |
| --- | --- | --- |
| FR-23 | 회원은 장바구니의 모든 항목과 배송지(저장된 배송지 또는 새로 입력한 주소)로 주문을 만든다. (2026-11-19 변경. 이전에는 "장바구니의 주문 가능한 모든 항목". 검증의 409 규칙과 맞춤, SDD 12.1절) 주문은 결제 대기로 만들어지고, 같은 트랜잭션에서 옵션 재고를 차감하고 주문한 장바구니 항목을 지운다(NFR-14). | `POST /api/orders/` 201, `status=PENDING`, 주문번호 형식 DR-11. 재고가 수량만큼 줄고 장바구니 항목 삭제. 한 항목이라도 재고 부족이면 409이고 재고·장바구니 그대로 |
| FR-24 | 주문 화면은 주문 항목, 상품 금액, 배송비, 최종 결제 금액을 보여준다(DR-14, DR-15). | 상품 금액 29,000원 주문의 배송비 3,000원, 30,000원 주문의 배송비 0원 |
| FR-25 | 회원이 주문 화면에서 결제하기를 누르면, 시스템은 FR-23으로 주문을 만든 뒤 결제 기록을 만들고 최종 결제 금액으로 PG 테스트 결제창을 연다. 결제 수단은 PG 결제창 안에서 고른다. 결제가 꺼져 있으면 FR-60을 따른다. (2026-11-27 FR-60 연결 추가) | `POST /api/orders/{id}/payments/` 201, 결제 기록 `status=READY` 1행, PG에 넘긴 금액 = 최종 결제 금액 |
| FR-26 | PG 결제창에서 돌아오면 프론트엔드가 PG 결과로 확인 API를 부르고, 서버는 결제 금액이 최종 결제 금액과 같으면 결제를 성공으로, 주문을 결제 완료로 바꾼다(DR-22). 결제가 꺼져 있으면 FR-60을 따른다. (2026-11-27 FR-60 연결 추가) | `POST /api/payments/confirm/`(회원 토큰) 200, 결제 `SUCCESS`, 주문 `PAID`. 결제 결과 화면에 주문번호 표시 |
| FR-27 | 확인 요청의 금액이 결제를 시작할 때의 금액과 다르면, 서버는 PG 승인을 부르지 않고 그 결제를 취소로 닫는다. PG 승인은 됐지만 승인 금액이 최종 결제 금액과 다르거나 주문이 이미 취소됐으면, 서버는 PG에 그 결제의 취소를 요청한다(DR-23). (2026-11-27 변경. 이전에는 "결제는 성공했지만 금액이 다르거나 주문이 이미 취소됐으면, 서버는 PG에 그 결제의 취소를 요청한다". PG는 결제창과 다른 금액의 승인을 거절하므로 확인 단계에서 닫는 구현과 맞춤, SDD 12.1절) | 금액이 다른 확인 요청 409 `PAYMENT_MISMATCH`, PG 호출 0회, 결제 `CANCELLED`, 주문 `PENDING` 유지. 취소된 주문은 `CANCELLED` 유지 |
| FR-28 | 결제가 실패하면 서버는 결제 기록을 실패로 바꾸고 사유를 저장한다. 주문은 결제 대기로 남는다(DR-24). | 결제 `FAILED` + 실패 사유, 주문 `PENDING` |
| FR-29 | 회원은 결제 대기 주문을 주문 상세에서 다시 결제한다(결제 실패, 결제창 이탈 모두). 결제가 꺼져 있으면 FR-60을 따른다. (2026-11-27 FR-60 연결 추가) | 결제 대기 주문 상세에 결제하기 버튼. FR-25 결제 요청 201, 결제 기록 1행 추가. 성공한 결제가 있는 주문은 409 |
| FR-30 | 회원은 자기 주문 목록을 최근 순으로 보고, 주문번호, 주문일, 최종 결제 금액, 상태를 확인한다. | `GET /api/orders/` 200, 자기 주문만, `created_at` 내림차순 |
| FR-31 | 회원은 자기 주문의 상세(주문 항목, 결제, 배송지, 상태)를 본다. | `GET /api/orders/{id}/` 200. 다른 회원 주문 404 |
| FR-32 | 회원은 결제 대기 주문을 바로 취소하고, 재고는 되돌아간다. | `POST /api/orders/{id}/cancel/` 200, `status=CANCELLED`, 재고 복구. 결제 완료 이후 상태 409 |
| FR-33 | 회원은 결제 완료나 배송 준비 주문에 사유를 적어 취소를 요청한다(DR-20). | `POST /api/orders/{id}/cancel-request/` 200, `status=CANCEL_REQUESTED`, 요청 전 상태와 사유 저장. 사유 비면 400, 배송 중 409 |
| FR-55 | 회원은 자기 주문 목록을 상태로 거른다. | `GET /api/orders/?status=PAID` 200, 그 상태 주문만 |
| FR-60 | 운영 서버에 PG 시크릿 키가 없으면 결제를 끈다. 결제 시작, 결제 확인, 관리자 취소 승인은 아무것도 바꾸지 않고 503 `PAYMENTS_DISABLED`로 멈추고, 다른 기능은 그대로 돈다. 주문 화면은 결제를 받을 수 없다는 안내와 이미 만든 주문의 상세 링크를 보여준다. (2026-11-27 추가) | 키 없는 설정에서 `POST /api/orders/{id}/payments/` 503, 결제 기록 0행, PG 호출 0회. 확인 요청 503 뒤 결제 `READY` 그대로, 취소 승인 503 뒤 주문 `CANCEL_REQUESTED` 그대로. 장바구니·주문 생성 정상. 주문 화면에 안내 문구와 `/orders/{id}` 링크 |
