## 4. 비기능 요구사항

NFR 하나에는 측정 가능한 조건 하나만 둔다. 측정 열은 숫자, 상태 코드, 도구 중 하나로 확인하는 방법이다. 운영 환경 주소는 `https://<도메인>`으로 쓴다(도메인 이름은 문서에 적지 않는다, 7.1절).

| ID | 분류 | 요구사항 | 측정 |
| --- | --- | --- | --- |
| NFR-1 | 성능 | 원두 목록 조회, 검색, 필터 API는 운영 환경에서 빠르게 응답한다. | 시연 데이터(NFR-3)로 각 경로 20회 요청, 서버 응답 시간 p95 500ms 이하 |
| NFR-2 | 성능 | 원두 목록 화면은 접속 후 2초 안에 목록을 표시한다. | Chrome DevTools, 캐시 비운 상태 5회, 목록 표시까지 평균 2초 이하 |
| NFR-3 | 성능 | 원두 100종, 회원 50명, 주문 500건 규모의 시연 데이터에서 NFR-1, NFR-2를 만족한다. | 시드 명령으로 데이터를 넣고 NFR-1, NFR-2 측정 |
| NFR-4 | 보안 | 브라우저와 서버 사이 통신은 HTTPS로만 한다. HTTP 요청은 HTTPS로 넘긴다. | `curl -I http://<도메인>/` 301 또는 308, `Location`이 `https://` |
| NFR-5 | 보안 | HTTPS 인증서가 유효하고 TLS 1.2 이상만 받는다. | `curl https://<도메인>/api/health/` 인증서 오류 없음. `openssl s_client -tls1_1` 연결 실패 |
| NFR-6 | 보안 | 비밀번호는 8자 이상이며 원문이 아니라 해시로만 저장한다. | DB `users.password` 열(SDD 11절 커스텀 사용자 모델)이 `pbkdf2_sha256$` 형식, 원문과 다름 |
| NFR-7 | 보안 | 로그인 실패 응답은 이메일이 있는지 알려주지 않는다(FR-8). | 없는 이메일과 틀린 비밀번호의 응답 상태 코드·본문 같음 |
| NFR-8 | 보안 | 회원 인증은 JWT로 한다. 액세스 토큰 유효 시간은 30분, 리프레시 토큰은 7일이다. | 토큰 `exp` − `iat`가 1,800초, 604,800초 |
| NFR-9 | 보안 | 로그인이 필요한 경로는 유효한 토큰 없이 쓸 수 없다. 비회원이 쓸 수 있는 경로는 원두 목록·상세, 회원가입, 로그인, 토큰 재발급, 상태 확인뿐이다. | 그 외 경로에 토큰 없이 요청하면 401 |
| NFR-10 | 보안 | 관리자 경로(`/api/admin/`)와 관리 화면은 관리자 권한 계정만 쓴다. | 회원 토큰으로 관리자 경로 요청 403 |
| NFR-11 | 보안 | 회원은 자기 장바구니, 배송지, 주문만 조회하고 고친다. | 다른 회원의 객체 ID로 요청하면 404 |
| NFR-12 | 보안 | 운영 환경은 디버그 모드를 끄고, 오류 응답에 스택 트레이스나 설정값을 넣지 않는다. | `DEBUG=False`. 없는 경로 404, 서버 오류 500 응답 본문에 파일 경로·코드 없음 |
| NFR-13 | 보안 | 시크릿(Django 비밀 키, PG 키 등)은 레포에 두지 않고 운영 환경 변수로 넣는다. 레포에는 이름만 적은 `.env.example`만 둔다. | `git grep`으로 키 값 검색 0건. 서버 `.env`는 소유자만 읽기(권한 600) |
| NFR-14 | 신뢰성 | 주문 생성과 재고 차감은 한 트랜잭션이다. 둘 중 하나만 반영되지 않는다. | 재고 부족 항목이 섞인 주문 요청 409 후 모든 옵션 재고와 주문 수 그대로 |
| NFR-15 | 신뢰성 | 여러 회원이 같은 옵션의 마지막 재고를 동시에 주문해도 재고가 0 밑으로 내려가지 않는다. | 재고 1개 옵션에 동시 주문 10건, 성공 1건, 재고 0 |
| NFR-16 | 신뢰성 | 품절·판매 중지 여부는 화면과 별개로 서버에서 다시 확인해 주문을 막는다. | 판매 중지 원두 옵션으로 직접 주문 요청 409 |
| NFR-17 | 신뢰성 | 주문 기록이 있는 회원은 삭제되지 않는다. | 주문 있는 회원 삭제 시도 실패, 회원 행 그대로 |
| NFR-18 | 개인정보 | 카드 번호 등 결제 수단 정보는 저장하지 않고 PG 거래번호만 저장한다. | 결제 테이블에 카드 정보 열 없음 |
| NFR-19 | 호환 | 프론트엔드는 React(Vite), 백엔드는 Django + Django REST Framework, DB는 SQLite, 런타임은 Python 3.12, Node.js 24 LTS다. | `backend/requirements.txt`, `frontend/package.json` 의존성. 운영 서버 `python3 --version` 3.12.x, 빌드 환경 `node --version` 24.x |
| NFR-20 | 운영 | 운영 환경은 AWS EC2 인스턴스 한 대이며, 웹 서버, 애플리케이션 서버, DB 파일이 모두 그 인스턴스에 있다. | SIP 1절 환경 표와 인스턴스 구성 일치 |
| NFR-21 | 운영 | 사용자는 Cloudflare에서 DNS를 관리하는 도메인 하나로 화면과 API에 접속한다. 화면은 `/`, API는 `/api/`다. | `dig <도메인>` 응답이 Cloudflare 이름 서버에서 옴. `https://<도메인>/`과 `/api/health/` 둘 다 200 |
| NFR-22 | 가용성 | 서버 재부팅이나 프로세스 종료 뒤 사람 손 없이 서비스가 다시 뜬다. | 인스턴스 재부팅 후 5분 안에 `/api/health/` 200, 수동 명령 0회 |
| NFR-23 | 가용성 | 운영 배포부터 시연·평가가 끝날 때까지(기간은 7.2절 미결) 서비스가 접속 가능하다. (2026-11-19 변경. 이전에는 출처 없는 기간 "2026-11-22 ~ 2026-12-06") | 외부에서 `/api/health/`를 5분마다 확인, 실패 비율 1% 이하 |
| NFR-24 | 운영 | 배포는 SIP 2절의 절차를 그대로 따라 누가 해도 같은 결과가 난다. 실패하면 직전 버전으로 되돌린다. | 배포 후 `/api/health/` 200과 화면 버전 표시가 배포한 커밋과 같음. 롤백 리허설 1회 성공 |
| NFR-25 | 운영 | DB 파일은 하루 한 번 백업하고 최근 7개를 남긴다. | 백업 폴더에 날짜별 파일 7개, 하나로 복원 리허설 1회 성공 |
| NFR-26 | 호환 | 화면은 최신 Chrome(데스크톱)에서 정상 동작한다. | Chrome 최신 안정판에서 UC-1 ~ UC-14 수동 확인 전부 통과 |
| NFR-27 | 유지보수 | 개발 환경은 Windows와 macOS에서 같은 절차로 설치하고 실행한다. | README Setup 절차를 두 OS에서 따라 해서 `/api/health/` 200 |
| NFR-28 | 유지보수 | 프론트엔드와 백엔드는 REST API로 JSON만 주고받는다. | API 응답 `Content-Type: application/json`(상태 확인 포함) |
| NFR-29 | 유지보수 | Python은 black, JavaScript는 prettier로 형식을 맞추고 oxlint를 통과한다. | `black --check`, `npx prettier --check`, `npm run lint` 오류 0 |
| NFR-30 | 품질 | 화면 문구는 한국어로 표시한다. | 모든 화면의 버튼·안내·오류 문구가 한국어 |
| NFR-31 | 유지보수 | 프론트엔드의 API 요청은 공통 axios 인스턴스 하나로만 보낸다. | `frontend/src`에서 `axios.create` 1곳, 다른 파일의 직접 `axios.get`·`fetch` 0건 |
| NFR-32 | 유지보수 | 화면 상태는 React `useState`와 props만 쓰고 상태 관리 라이브러리를 넣지 않는다. | `package.json`에 redux·zustand·recoil 등 없음 |
| NFR-33 | 품질 | 가격은 원 단위에 천 단위 쉼표를 붙여 표시한다. | 29000 → `29,000원` |
| NFR-34 | 품질 | 입력이 잘못되거나 요청이 실패하면 무엇이 잘못됐는지 화면에 알려준다. | 400 응답의 필드 오류가 해당 입력 옆에 표시됨 |
| NFR-35 | 개인정보 | 서버 로그에 비밀번호, 토큰, 연락처, 주소를 남기지 않는다. | 로그인·주문 요청 뒤 서버 로그에서 해당 값 검색 0건 |
| NFR-36 | 운영 | 모든 화면 맨 위에 "학교 과제 데모입니다. 실제 판매와 결제는 이뤄지지 않습니다." 고지 배너를 늘 보인다. (2026-11-19 추가) | SCR-01 ~ SCR-15와 결제 결과 화면 각각에서 배너 문구 표시, 닫는 버튼 없음 |
