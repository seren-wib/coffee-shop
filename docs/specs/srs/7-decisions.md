## 7. 확정과 미결

### 7.1 확정

- 2026-11-17: 실행 환경을 로컬 PC 시연에서 AWS EC2 배포로 바꾸고, 도메인 DNS는 Cloudflare에서 관리한다(NFR-20, NFR-21). 버린 것: 로컬 PC 시연(HW1 상정. 평가자가 직접 접속해 볼 수 없고 배포·운영 요구사항을 다룰 수 없음). 이유: 설치·유지보수 계획서(SIP, SMP)까지 실제 환경으로 검증할 수 있다. (팀장 결정)
- 2026-11-17: 결제는 PG 테스트 모드만 쓰고 실제 결제는 하지 않는다. 버린 것: 실결제(사업자 등록과 PG 계약 필요). 이유: 비용, 법적 조건. (HW1 범위 유지)
- 2026-11-17: 배송 추적은 택배사 조회 페이지 링크로 한다. 버린 것: 택배사 API 연동(API 키 발급과 택배사별 형식 차이). 이유: 종속성, 범위. (HW1 범위 유지)
- 2026-11-17: 일정 시간이 지난 결제 대기 주문의 자동 취소는 범위 밖이다. 재고는 회원이 취소할 때 되돌린다. (HW1 범위 유지)
- 2026-11-17: 화면 흐름은 HW1 와이어프레임을 따른다. 주문은 장바구니 전체로 하고, 결제하기 한 번에 주문 생성과 결제창 열기를 한다. 버린 것: 장바구니 항목 골라 주문(와이어프레임에 선택 UI 없음), 주문 확정과 결제를 두 번 누르기(제출한 화면 설계와 다름). (HW1 설계 유지)
- 2026-11-17: 이번 학기 범위 전체를 1차로 두고 차수를 나누지 않는다. 이유: 마감(2026-11-30 23:50)까지 한 번에 배포한다. (2026-11-19 변경. 이전에는 마감을 2026-12-06으로 적었으나 출처가 없었다. 마감은 팀장이 2026-11-19에 전달한 텀프로젝트 마감이다. 2026-11-27 변경: 24:00 → 23:50, LMS 과제 "텀프로젝트 최종 개발문서" 마감)

- 2026-11-17: 비기능 수치를 NFR-1 p95 500ms, NFR-3 주문 500건, NFR-8 액세스 토큰 30분·리프레시 토큰 7일, NFR-23 실패 비율 1%, NFR-25 백업 7개로 정한다. 버린 것: simplejwt 기본값 액세스 5분·리프레시 1일(시연 중 재로그인이 잦음), 백업 없음(EC2 디스크 하나에 데이터 전부). 이유: 시연 규모(NFR-3)에서 측정 가능하고, 테스트로 확인할 수 있는 값. (커피샵 Lead 제안, 팀장 위임)
- 2026-11-17: PG는 토스페이먼츠 테스트 모드를 쓴다. 결제창에서 돌아오면 프론트엔드가 결과(결제 키, 주문 ID, 금액)를 확인 API로 보내고 서버가 PG 승인 API를 부른다(FR-26). 웹훅은 받지 않는다. 버린 것: 웹훅 수신(인증 없는 공개 경로가 생겨 NFR-9 예외가 필요하고, 시연에선 결제창 복귀만으로 충분), 결제 연동 대행 서비스(의존 서비스가 하나 더 늘어남). 이유: 사업자 등록 없이 테스트 키로 쓸 수 있고, 복귀 후 서버 승인 흐름이 DR-22, DR-23 검증 위치와 맞음. (커피샵 Lead 결정, 팀장 위임)
- 2026-11-17: 지원 택배사는 CJ대한통운, 한진택배, 롯데택배, 우체국택배, 로젠택배 다섯 곳의 고정 목록이다(FR-35, FR-48). 조회 페이지 주소 규칙은 SDD 데이터 모델에 둔다. 버린 것: 택배사 자유 입력(조회 링크를 만들 수 없음). 이유: 테스트 용이성. (커피샵 Lead 결정, 팀장 위임)
- 2026-11-17: 상품 이미지는 관리자가 입력하는 이미지 URL 한 칸(선택)으로 한다. 서버에 파일을 올리지 않고, 비어 있으면 기본 이미지를 보여준다. 버린 것: 서버 업로드(EC2 디스크 용량, 백업 범위, 업로드 검증이 늘어남), 이미지 없음(HW1 와이어프레임 SCR-01, SCR-02, SCR-05에 이미지 자리가 있음). 이유: 유지보수성, 종속성. (커피샵 Lead 결정, 팀장 위임)
- 2026-11-17: 문서에는 운영 도메인 이름을 적지 않고 "도메인"(`<도메인>`)으로만 표기한다. 실제 이름은 서버 설정에만 둔다(SDD 11.1절). 버린 것: 문서에 이름 적기(공개 레포에 운영 주소가 남고, 이름이 바뀌면 문서를 고쳐야 함). (팀장 결정. 2026-11-19 7.2 미결에서 옮김)
- 2026-11-19: 개인정보 수집·이용 동의(FR-58), 개인정보 처리방침 페이지(FR-59), 데모 고지 배너(NFR-36)를 요구사항에 넣는다. 이용약관은 두지 않는다. 버린 것: 이용약관 동의(결제는 토스페이먼츠 테스트 모드뿐이라 약관이 정할 실제 거래 조건이 없음), 안내 없이 가입(공개 주소라 실제 사람이 가입할 수 있는데 무엇을 왜 언제까지 받는지 알 수 없음). 이유: 받는 개인정보와 데모라는 사실을 화면에 남긴다. (팀장 결정)
- 2026-11-27: CI/CD를 요구사항에 넣는다(NFR-37 ~ NFR-39, FR-61, FR-62, UC-15). 채택: GitHub Actions가 PR과 `main` push마다 검사하고(CI), 배포는 운영자가 CI를 통과한 `main` 커밋의 릴리스 태그로 서버에서 배포 명령을 실행한다(CD, 수동 실행). 버린 것: Actions 자동 배포(SSH 키를 Actions 시크릿에 두고 22번을 GitHub 주소 대역에 열어야 함), CI 없이 PR 작성자가 확인(깨진 `main`을 막을 수단이 없음), 검사·배포 조건을 STP·SDD에만 두기(HW1처럼 범위가 "로컬 시연"으로 읽히고 SRS에서 테스트·배포까지 추적이 끊김). 이유: 보안, 테스트 용이성. HW1이 실행 환경을 "로컬 PC에서만"으로 잡아 빠졌던 것을 정정한다. (팀장 결정)
- 2026-11-27: 결제 끔과 테스트 키 강제를 요구사항에 넣는다(FR-60, NFR-42). 채택: PG 시크릿 키가 없으면 결제 시작·확인·관리자 취소 승인만 503으로 막고 나머지는 운영한다. 테스트 키가 아니면 서버가 뜨지 않는다. 버린 것: 다른 프로젝트와 함께 쓰는 테스트 키를 운영에 두기(그 상점의 결제와 섞임), 결제 경로를 URL에서 빼기(화면이 404와 503을 따로 처리해야 함), 라이브 키(사업자 등록과 실결제 필요). 이유: 보안, 법적 조건. (SDD 11.1절 2026-11-19 결정을 요구사항으로 올림, 팀장 결정)
- 2026-11-27: 배포 실패 처리를 요구사항에 넣는다(FR-62, FR-63, NFR-40, NFR-41). 채택: 새 릴리스로 바꾸기 전 실패는 멈추고, 바꾼 뒤 상태 확인 실패는 자동으로 직전 릴리스로 되돌리고, 마이그레이션 전에 DB를 백업한다. 버린 것: 손으로만 되돌리기(시연 직전 배포가 실패하면 복구가 늦음), 블루그린이나 인스턴스 두 대(t3.micro 한 대 범위를 넘고 비용이 늘어남). 이유: 가용성(NFR-23), 비용. (SDD 10.4절, 팀장 결정)
- 2026-11-27: HW1 비기능 요구사항(유지보수성)의 "모든 변경은 이슈와 브랜치를 만들어 작업하고 PR을 거쳐 main에 합친다"는 NFR-38로 옮긴다. "코드, 주석, 커밋 메시지는 영어, 제출 문서는 한국어"는 요구사항에 두지 않고 CONTRIBUTING 규칙으로 둔다. 이유: 시스템이 아니라 개발 방식에 대한 규칙이라 측정할 시스템 조건이 아니다. (팀장 결정)
- 2026-11-17: 배포 방식, 사용자 모델, 관리 사이트, 테이블 정의 원본, 시간대처럼 구현 수단에 대한 결정은 SDD 11절 설계 근거에 둔다.
